# Сборка и установка ProxysVPN Desktop

Сборку делают раннеры GitHub (`.github/workflows/desktop-build.yml`): macOS (Apple Silicon),
Windows x86_64, Linux x86_64. Ничего не подписывается и никуда не публикуется — готовые файлы
кладутся в артефакты запуска и лежат там 14 дней. Секреты репозитория не используются.

## 1. Запустить сборку

1. GitHub → репозиторий `evilork/proxysvpn-desktop` → вкладка **Actions**.
2. Слева выбрать воркфлоу **desktop-build** → кнопка **Run workflow**.
3. Выбрать ветку (например `main`) → **Run workflow**.

Та же сборка запускается сама на каждый pull request, который трогает приложение
(`src/`, `src-tauri/`, `scripts/`, `package.json`, конфиги сборки).

Три задания идут параллельно, каждое 10–25 минут. Одно упавшее задание не отменяет остальные.

## 2. Скачать готовые файлы

Открыть завершившийся запуск → внизу страницы раздел **Artifacts**:

| Артефакт | Что внутри |
| --- | --- |
| `proxysvpn-macos-aarch64` | `ProxysVPN_<версия>_aarch64.dmg` |
| `proxysvpn-windows-x86_64` | `ProxysVPN_<версия>_x64-setup.exe` (установщик NSIS) |
| `proxysvpn-linux-x86_64` | `proxysvpn-desktop_<версия>_amd64.deb` и `ProxysVPN_<версия>_amd64.AppImage` |

GitHub отдаёт артефакт одним zip-архивом — распаковать перед установкой.

## 3. macOS (Apple Silicon)

```bash
# после распаковки артефакта
open ProxysVPN_0.1.0_aarch64.dmg          # смонтировать образ
# перетащить ProxysVPN.app в «Программы», образ размонтировать
xattr -cr /Applications/ProxysVPN.app     # снять карантин: сборка без подписи Apple
open /Applications/ProxysVPN.app
```

При запуске приложение само просит пароль администратора — так и должно быть: туннелю нужен root.
Если окно с паролем зацикливается, значит `.dmg` собран не через `src-tauri/scripts/build-release.sh`
(в воркфлоу macOS собирается именно им).

## 4. Windows 10 / 11, 64 бита

1. Распаковать zip, запустить `ProxysVPN_<версия>_x64-setup.exe`.
2. SmartScreen покажет «Windows защитила ваш компьютер» — подписи кода у нас нет.
   **Подробнее** → **Выполнить в любом случае**.
3. Установщик ставит приложение для всех пользователей и просит подтверждение UAC.
4. Приложение при каждом запуске просит UAC — без прав администратора туннель не поднять.

Windows 11 содержит WebView2 изначально. На Windows 10 установщик докачивает его из интернета,
поэтому первая установка требует сети.

## 5. Linux x86_64

`.deb` (Ubuntu/Debian, рекомендуется — ставит зависимости сам):

```bash
sudo apt install ./proxysvpn-desktop_0.1.0_amd64.deb
```

AppImage (любой дистрибутив, ничего не ставится в систему):

```bash
chmod +x ProxysVPN_0.1.0_amd64.AppImage
./ProxysVPN_0.1.0_amd64.AppImage
```

Замечания:

- Сборка идёт на Ubuntu 22.04, поэтому файлы работают на 22.04 и новее (glibc 2.35+).
- Значок в трее требует пакета `libayatana-appindicator3-1`; `.deb` тянет его сам, для AppImage
  поставить вручную.
- Туннелю нужны права на сеть (`CAP_NET_ADMIN`): при подключении система спросит пароль.

## 6. Что в этих сборках не проверено

Честно, без умолчаний:

- Сборки под Windows и Linux ни разу не запускались на живой машине — на этом Mac нет ни Windows,
  ни Linux, ни Docker. Проверка возможна только на раннерах и на реальных машинах.
- Код под Windows и Linux **компилируется** — целиком, вместе с FFI и корневым помощником, —
  но только проверкой компилятора. Это делает задание `cross-check` в CI и
  `scripts/check-platform.sh` локально:

  ```
  scripts/check-platform.sh
  ```

  Оно собирает платформенный слой под `x86_64-pc-windows-msvc` и
  `x86_64-unknown-linux-gnu` прямо на Mac и гоняет `clippy -D warnings`. Это
  возможно потому, что слой вынесен в отдельный крейт `pvpn-platform` без
  tauri/reqwest/rustls — то есть без `ring`, который требует C-компилятора.
  Что это НЕ доказывает: что приложение линкуется целиком, что `netsh` и `ip`
  принимают каждое написание аргумента, что tun2socks назовёт адаптер так, как мы
  ждём, и что pkexec ведёт себя как надо в живой сессии.
- Подписи нет ни у одной сборки: macOS требует `xattr -cr`, Windows пугает SmartScreen'ом.
  Сертификат (Apple Developer ID, Windows EV) — отдельное решение владельца.
