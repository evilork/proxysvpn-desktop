# Сборка и установка ProxysVPN Desktop

Сборку делают раннеры GitHub (`.github/workflows/desktop-build.yml`): macOS (Apple Silicon),
Windows x86_64, Windows ARM64 (на раннере `windows-11-arm`, без эмуляции), Linux x86_64
(`.deb` и AppImage — сборка для Steam Deck).
Ничего не подписывается и никуда не публикуется. Секреты репозитория не используются.

**Установщики по умолчанию никуда не выкладываются.** Репозиторий публичный, и артефакты
запуска может скачать любой вошедший пользователь GitHub. Поэтому pull request и push в `main`
только собирают, проверяют и упаковывают (поломка упаковки всё равно роняет прогон), а файлы
остаются на раннере. Выложить их в артефакты (на 14 дней) можно только ручным запуском с
отметкой `upload_installers` — это решение «сборку можно показывать», и принимает его владелец.

## 1. Запустить сборку

1. GitHub → репозиторий `evilork/proxysvpn-desktop` → вкладка **Actions**.
2. Слева выбрать воркфлоу **desktop-build** → кнопка **Run workflow**.
3. Выбрать ветку (например `main`). Нужны файлы — отметить **upload_installers**
   (их увидит любой вошедший в GitHub) → **Run workflow**.

Та же сборка без выкладки файлов запускается сама на каждый pull request и push в `main`,
которые трогают приложение (`src/`, `src-tauri/`, `scripts/`, `package.json`, конфиги сборки).

Пять заданий сборки идут параллельно, каждое 10–25 минут (сколько займут ARM64 и AppImage,
покажет первый прогон). Одно упавшее задание не отменяет остальные.

## 2. Скачать готовые файлы

Открыть завершившийся ручной запуск с `upload_installers` → внизу страницы раздел **Artifacts**:

| Артефакт | Что внутри |
| --- | --- |
| `proxysvpn-macos-aarch64` | `ProxysVPN_<версия>_aarch64.dmg`, `SHA256SUMS-proxysvpn-macos-aarch64.txt` |
| `proxysvpn-windows-x86_64` | `ProxysVPN_<версия>_x64-setup.exe` (установщик NSIS), `SHA256SUMS-proxysvpn-windows-x86_64.txt` |
| `proxysvpn-windows-arm64` | `ProxysVPN_<версия>_arm64-setup.exe` (установщик NSIS для Windows on ARM), `SHA256SUMS-proxysvpn-windows-arm64.txt` |
| `proxysvpn-linux-x86_64` | `ProxysVPN_<версия>_amd64.deb`, `SHA256SUMS-proxysvpn-linux-x86_64.txt` |
| `proxysvpn-linux-appimage` | `ProxysVPN_<версия>_amd64.AppImage` (Steam Deck и любой Linux x86_64), `SHA256SUMS-proxysvpn-linux-appimage.txt`, `LGPL-SOURCES-linux-appimage.txt` (из каких пакетов Ubuntu и каких версий взяты библиотеки образа; THIRD-PARTY-NOTICES.md) |

GitHub отдаёт артефакт одним zip-архивом — распаковать перед установкой. Оба файла лежат
в корне архива, без подпапок. `scripts/publish-release.sh` ищет установщики и файлы
`SHA256SUMS-*.txt` и во вложенных папках (старые артефакты клали их в `dmg/`, `nsis/`,
`deb/`) и останавливается, если какой-то установщик в этих файлах не указан или его
сумма не совпадает. `.dmg`, `x64-setup.exe` и `.deb` обязательны; `arm64-setup.exe` и `.AppImage`
прикладываются к релизу, если лежат в папке, как и `LGPL-SOURCES-linux-appimage.txt`
(в `SHA256SUMS.txt` он не входит: это не установщик, и та же копия лежит внутри образа).
Если прогон такой установщик собрал (он указан в его `SHA256SUMS-*.txt`), а в папке файла
нет, скрипт останавливается: значит, скачаны не все артефакты.

Подписи кода у сборок нет, поэтому единственная проверка «это тот самый файл» —
sha256. Прогон печатает его сам: в логе задания есть шаг **List bundle output
with checksums**. Сверить после распаковки:

```bash
shasum -a 256 ProxysVPN_0.3.1_aarch64.dmg          # macOS
certutil -hashfile ProxysVPN_0.3.1_x64-setup.exe SHA256   # Windows
sha256sum ProxysVPN_0.3.1_amd64.deb                # Linux
```

## 3. macOS (Apple Silicon)

```bash
# после распаковки артефакта
open ProxysVPN_0.3.1_aarch64.dmg          # смонтировать образ
# перетащить ProxysVPN.app в «Программы», образ размонтировать
xattr -cr /Applications/ProxysVPN.app     # снять карантин: сборка без подписи Apple
open /Applications/ProxysVPN.app
```

При запуске приложение само просит пароль администратора — так и должно быть: туннелю нужен root.
Если окно с паролем зацикливается, значит `.dmg` собран не через `src-tauri/scripts/build-release.sh`
(в воркфлоу macOS собирается именно им).

## 4. Windows 10 / 11, 64 бита

1. Распаковать zip, запустить `ProxysVPN_<версия>_x64-setup.exe`.
2. SmartScreen покажет «Windows защитила ваш компьютер» — подписи кода у нас нет.
   **Подробнее** → **Выполнить в любом случае**.
3. Установщик ставит приложение для всех пользователей и просит подтверждение UAC.
4. Приложение при каждом запуске просит UAC — без прав администратора туннель не поднять.

Windows 11 содержит WebView2 изначально. На Windows 10 установщик докачивает его из интернета,
поэтому первая установка требует сети.

На компьютере с процессором ARM (Snapdragon и т. п., Windows 11) ставить
`ProxysVPN_<версия>_arm64-setup.exe` из артефакта `proxysvpn-windows-arm64`: в нём xray, tun2socks,
hysteria и `wintun.dll` собраны под ARM64. Сборка x64 там тоже работает, но через эмуляцию, и
подключение на виртуальной машине занимало от 30 с до 2 мин (подробности — `docs/WINDOWS.md`).
На обычном x64-компьютере сборка ARM64 не запустится.

## 5. Linux x86_64

`.deb` (Ubuntu/Debian, ставит зависимости сам):

```bash
sudo apt install ./ProxysVPN_0.3.1_amd64.deb
```

AppImage (Steam Deck и любой Linux x86_64, ничего не ставит в систему):

```bash
chmod +x ProxysVPN_0.3.1_amd64.AppImage && ./ProxysVPN_0.3.1_amd64.AppImage
```

Root не может запускать файлы из её FUSE-монтирования, поэтому при первом подключении одно
окно пароля копирует помощника с правами и tun2socks в `/home/.proxysvpn/bin` (владелец root,
суммы проверяются), и дальше запускается эта копия. На Steam Deck сначала нужно задать пароль
пользователю `deck` (`passwd` в Konsole) и первый раз подключиться в режиме рабочего стола;
после этого игровой режим подключается без пароля. Подробно, с удалением и тем, что настройка
оставляет в системе, — `docs/STEAMDECK.md`.

Замечания:

- Сборка идёт на Ubuntu 22.04, поэтому файлы работают на 22.04 и новее (glibc 2.35+).
- Значок в трее требует `libayatana-appindicator3-1`, а запрос пароля — `pkexec` (polkit); `.deb`
  тянет оба сам.
- Туннелю нужны права на сеть (`CAP_NET_ADMIN`): при подключении система спросит пароль.

## 6. Что в этих сборках не проверено

Честно, без умолчаний:

- Сборки под Windows и Linux ни разу не запускались на живой машине — на этом Mac нет ни Windows,
  ни Linux, ни Docker. Проверка возможна только на раннерах и на реальных машинах.
- Код под Windows и Linux **компилируется** — целиком, вместе с FFI и корневым помощником, —
  но только проверкой компилятора. Это делает задание `cross-check` в CI и
  `scripts/check-platform.sh` локально:

  ```
  scripts/check-platform.sh
  ```

  Оно собирает платформенный слой под `x86_64-pc-windows-msvc`, `aarch64-pc-windows-msvc` и
  `x86_64-unknown-linux-gnu` прямо на Mac и гоняет `clippy -D warnings`. Цель, которую rustup
  не поставил, пропускается с предупреждением и готовой командой `rustup target add …`, а
  остальные проверяются; в CI (`CI=true`) недостающая цель — ошибка. Это
  возможно потому, что слой вынесен в отдельный крейт `pvpn-platform` без
  tauri/reqwest/rustls — то есть без `ring`, который требует C-компилятора.
  Что это НЕ доказывает: что приложение линкуется целиком, что `netsh` и `ip`
  принимают каждое написание аргумента, что tun2socks назовёт адаптер так, как мы
  ждём, и что pkexec ведёт себя как надо в живой сессии.
- AppImage с копией помощника в `/home/.proxysvpn` (и всё про Steam Deck) не запускалась ни на одной
  машине: проверены компиляция под Linux и модульные тесты, включая сам скрипт установки под `sh`.
  Что осталось проверить вживую — в конце `docs/STEAMDECK.md`.
- Подписи нет ни у одной сборки: macOS требует `xattr -cr`, Windows пугает SmartScreen'ом.
  Сертификат (Apple Developer ID, Windows EV) — отдельное решение владельца.
