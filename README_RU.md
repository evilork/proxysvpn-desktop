# ProxysVPN Desktop

> 🇬🇧 [English version](README.md)

VPN-клиент для компьютера под сервис [ProxysVPN](https://proxysvpn.com) —
**macOS, Windows и Linux**. Пропускает IPv4-трафик системы через узел VLESS
(Reality / XHTTP) или Hysteria2 с раздельной маршрутизацией сервиса:
российские сайты и всё из вашего списка «всегда напрямую» идут напрямую.

## Возможности

- **Туннель на всю систему** через TUN-устройство и `tun2socks` (`utun225` на
  macOS, адаптер Wintun `ProxysVPN` на Windows, `proxysvpn0` на Linux). Пока
  только IPv4 — см. [Известные ограничения](#известные-ограничения).
- **VLESS Reality / XHTTP и Hysteria2.** xray всегда стоит первым в цепочке,
  поэтому правила раздельной маршрутизации действуют на любом протоколе.
- **Привязка без ввода ссылки:** код из 8 символов из кабинета или бота либо
  QR-код, который сканируется телефоном.
- **Чинится сам:** упавший движок перезапускается, узел, который перестал
  пропускать, заменяется другим, и окно говорит, что произошло.
- **Значок в трее** с пунктами «Открыть окно», «Выключить защиту», «Выйти»;
  закрытие окна не разрывает VPN.
- **Русский и английский** интерфейс.

## Скачать и установить

Установщики лежат на [странице релизов](https://github.com/evilork/proxysvpn-desktop/releases).
Подписи кода пока нет (ни Apple Developer ID, ни сертификата Windows), поэтому
каждая система один раз предупреждает. Перед установкой сверьте SHA-256
установщика с файлом `SHA256SUMS.txt` на странице релиза:

```bash
shasum -a 256 ProxysVPN_*            # macOS
sha256sum ProxysVPN_*                # Linux
certutil -hashfile ProxysVPN_<версия>_x64-setup.exe SHA256   # Windows
```

### macOS (Apple Silicon)

1. Откройте `ProxysVPN_<версия>_aarch64.dmg` и перетащите **ProxysVPN** на
   ярлык **Applications**.
2. Один раз снимите карантин загрузки, в Терминале:
   `xattr -dr com.apple.quarantine /Applications/ProxysVPN.app`
   (или запустите приложение, нажмите **«Готово»**, затем Системные настройки →
   Конфиденциальность и безопасность → **«Всё равно открыть»**; с macOS 15
   «правый клик → Открыть» больше не работает).
3. Запустите ProxysVPN и введите пароль администратора — он нужен туннелю.
4. Привяжите приложение кодом или QR из кабинета / бота либо вставьте ссылку.

Подробности и решение проблем: [INSTALL.md](INSTALL.md).

### Windows 10 / 11 (x64)

Установщик пока не подписан сертификатом издателя, поэтому Windows
предупредит дважды: при скачивании и при запуске. Сверьте SHA-256 файла с
`SHA256SUMS.txt` на странице релиза, если хотите убедиться, что файл наш.

1. Скачайте `ProxysVPN_<версия>_x64-setup.exe`. Microsoft Edge может
   остановить загрузку словами «Перед открытием файла убедитесь, что вы ему
   доверяете» и показать кнопку «Удалить». Кнопка сохранения спрятана рядом:
   **стрелка справа от «Удалить» → «Всё равно сохранить»**.
2. Запустите файл. SmartScreen скажет, что издатель неизвестен:
   **«Подробнее» → «Выполнить в любом случае»**.
3. Разрешите запрос прав администратора (UAC). Приложение просит их при
   каждом запуске: оно создаёт адаптер туннеля и маршруты.
4. Привяжите приложение кодом или QR либо вставьте ссылку.

**Windows на ARM** (Snapdragon, Surface Pro X): берите
`ProxysVPN_<версия>_arm64-setup.exe`, шаги те же. Файл x64 там тоже
работает, но через эмуляцию. На настоящем ARM-компьютере эта сборка ещё не
запускалась: она собрана и проверена на ARM-машине сборочного сервера.

### Linux (x86_64, .deb)

```bash
sudo apt install ./ProxysVPN_<версия>_amd64.deb
```

Запустите **ProxysVPN** из меню приложений. Первое подключение покажет окно
пароля polkit (в сеансе нужен агент polkit: он есть в GNOME, KDE, Xfce,
Cinnamon и MATE). Удаление: `sudo apt remove proxys-vpn`.

### Steam Deck (AppImage)

Файл `ProxysVPN_<версия>_amd64.AppImage`. Сделайте его исполняемым
(`chmod +x`), первый запуск и первое подключение — в режиме рабочего стола.
Дальше приложением можно пользоваться в игровом режиме, с геймпада. Все шаги,
раскладка контроллера и список того, что не проверено без самой приставки, —
в [docs/STEAMDECK.md](docs/STEAMDECK.md). На настоящей Steam Deck сборка ещё
не запускалась.

## Системные требования

- **macOS** 12 Monterey или новее, Apple Silicon (Mac на Intel не поддерживаются).
- **Windows** 10 или 11, x64 (проверено на Windows 11). WebView2 установщик
  поставит сам, если его нет.
- **Linux** x86_64 с glibc 2.35+ (Debian 12+, Ubuntu 22.04+; проверено на
  Debian 13), сеанс рабочего стола с агентом polkit, `iproute2`.

## Известные ограничения

- **IPv6 идёт в туннель, но выхода по IPv6 у серверов нет.** Сайты, как и
  раньше, открываются по IPv4 через VPN-сервер. Программа, которая сама нашла
  IPv6-адрес и соединяется с ним не по HTTPS и не по HTTP (некоторые игры и
  звонки), соединения по IPv6 при включённом VPN не получает и должна сама
  перейти на IPv4. Для имён, которые разрешает само приложение, IPv6-адреса не
  выдаются.
- **Если система отказала в заслоне IPv6, подключение всё равно происходит.**
  Идёт ли IPv6 мимо VPN, показывает строка «Утечек нет» на экране «Проверка».
  Отказанный заслон приложение ставит заново только в первые секунды после
  подключения (около сорока) и только на Windows. Заслон, который так и не
  встал, позже в этом сеансе не ставится, даже если сеть начнёт выдавать IPv6:
  строка это покажет, а переподключение попробует снова.
  Более точный IPv6-маршрут, который объявила сама сеть, сильнее двух маршрутов
  приложения: строка видит обычный случай (маршрут для всех публичных адресов)
  и не видит маршрут для более узкого диапазона; ни тот, ни другой приложение
  не исправляет.
- **Windows: имена всё ещё могут идти мимо VPN в трёх случаях.** Пока VPN
  включён, приложение не пропускает обычный DNS (порты 53 и 853) ни через один
  сетевой адаптер, кроме своего. Не закрыто: резолвер «Системный», выбранный в
  настройках туннеля (тогда не запрещается ничего), DNS поверх HTTPS,
  включённый в самой Windows, и имена в локальной сети (LLMNR, mDNS, NetBIOS).
- **macOS и Linux: экран «Проверка» пока не проверяет DNS.** Системный
  резолвер там указывает в туннель; строка «Утечек нет» проверяет только IPv6
  и прямо говорит об этом, поэтому зелёной на этих двух системах она не бывает.
- **Нет подписи кода и автообновления.** Новые версии ставятся вручную со
  страницы релизов.
- **macOS:** после сбоя или принудительного завершения движки могут работать,
  пока ProxysVPN не открыт снова; при открытии приложение их останавливает.
- **macOS:** всё приложение работает от root (пока нет подписанного
  привилегированного помощника). Движки (xray, tun2socks, hysteria) и их
  geo-файлы при запуске копируются в папку, принадлежащую root, и запускаются
  только оттуда, но само приложение (`Contents/MacOS/ProxysVPN-bin`) и его
  лаунчер по-прежнему запускаются от root прямо из бандла, а после
  перетаскивания в «Программы» бандл принадлежит вашей учётной записи.
  Программа, работающая под вашим пользователем, может их подменить, и подмена
  запустится от root при следующем запуске, когда вы введёте пароль. Решение —
  установщик `.pkg` с маленьким привилегированным помощником, чтобы окно больше
  не работало от root; оно запланировано.

## Приватность

- **Никакой телеметрии и аналитики.** Приложение обращается к:
  - сайту вашей ссылки подписки и, если это наш сайт и он не отвечает, к
    резервным `proxysvpn.com`, `proxysvnovich.vercel.app`, `proksya.com`,
    `proksya.xyz` (подписка, подписанный список серверов, привязка). В этих
    запросах есть токен ссылки и случайный идентификатор устройства
    (`x-hwid`): так сервис соблюдает правило «одна ссылка — одно устройство»;
  - VPN-узлам из подписки;
  - пока вы подключены — к проверке, что туннель пропускает трафик:
    `proxysvpn.store/api/exit-ip` и страница `/api/tools/whoami` резервных
    сайтов, через туннель;
  - DNS: Cloudflare (DNS-over-HTTPS) и Google, через VPN-узел (или резолвер,
    выбранный в настройках туннеля).
- **Журнал остаётся на устройстве:** `~/Library/Logs/ProxysVPN/app.log`
  (macOS), `%LOCALAPPDATA%\ProxysVPN\logs\app.log` (Windows),
  `~/.local/state/ProxysVPN/app.log` (Linux). Адреса узлов, токены и имена
  открытых вами сайтов маскируются до записи строки; файлы журнала, оставшиеся
  от прежней версии, маскируются так же один раз — при первом запуске версии,
  в которой изменились правила маскирования. «Отчёт для поддержки» покидает
  устройство, только если вы отправите его сами.
- **То, что приложение запоминает о сети, остаётся на устройстве:** какая
  локация в ней заработала и, когда это сказано в подписанном списке серверов,
  страна и сеть провайдера (номер AS), откуда сервис увидел ваш запрос, чтобы
  первым пробовать сервер, который в такой сети работает. Сама сеть записана
  солёным хешем, без имени и адреса, и никуда это не отправляется.
- **Никаких аккаунтов в приложении.** Оно привязано к вашей ссылке подписки.

## Удаление

- **macOS:** перенесите ProxysVPN в Корзину, затем
  `sudo rm -rf "/Library/Application Support/ProxysVPN"` и удалите
  `~/Library/Application Support/com.proxysvpn.desktop` и
  `~/Library/Logs/ProxysVPN`.
- **Windows:** Параметры → Приложения → ProxysVPN → Удалить, затем удалите
  папку `%LOCALAPPDATA%\ProxysVPN` (деинсталлятор её пока не трогает, а в ней
  ссылка, идентификатор устройства и журнал).
- **Linux:** `sudo apt purge proxys-vpn`, затем удалите
  `~/.local/share/ProxysVPN` и `~/.local/state/ProxysVPN`.

## Лицензия

В этом репозитории лежат установщики, документы к ним и сведения о
компонентах, которые в них входят. Исходный код самого приложения здесь не
публикуется.

В установщиках есть сторонние компоненты под своими лицензиями: Xray-core
(MPL-2.0), Hysteria (MIT), tun2socks (MIT), Wintun на Windows (лицензия
WireGuard LLC на готовые бинари), Tauri (MIT/Apache-2.0) и другие. Стоковые
бинари Xray-core и Hysteria содержат и Go-модули под GPL-3.0-or-later.
[THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) и экран «Лицензии открытого ПО»
в приложении перечисляют с версиями и исходниками движки, все Rust-крейты и
npm-пакеты приложения и эти GPL-модули. Остальные Go-модули, вкомпилированные
в движки для компьютеров (под MIT, BSD, Apache-2.0 и похожими лицензиями),
поштучно пока не перечислены; их выводит `go version -m <файл движка>`.

Исходники наших собственных правок Xray-core (MPL-2.0) — для сборок, где мы
компилируем движок сами, — лежат в [scripts/libxray](scripts/libxray).
